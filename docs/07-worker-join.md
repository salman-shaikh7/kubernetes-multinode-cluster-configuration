# Worker join

## Protect bootstrap credentials

Kubeadm bootstrap tokens and certificate hashes are temporary cluster credentials. Never commit a generated join command to this repository or publish it in screenshots and terminal output. Generate a fresh command when it is needed and allow unused tokens to expire.

## Generate and run the join command

Joining a worker establishes trust with the control plane, downloads the cluster configuration, and registers the worker's kubelet with the API server. The scheduler can then place Pods on that node.

Generate a fresh join command on the control plane:

```bash
sudo kubeadm token create --print-join-command
```

Run the generated command with `sudo` on both `k8s-worker-1` and `k8s-worker-2`. It will have this shape:

```bash
sudo kubeadm join 192.168.122.131:6443 \
  --token <bootstrap-token> \
  --discovery-token-ca-cert-hash sha256:<ca-certificate-hash>
```

The bootstrap token authorizes the initial join. The CA certificate hash prevents the worker from trusting an API server that is impersonating this cluster. Both placeholders must be replaced by the values generated by kubeadm.

## Verify node registration

From the control plane, verify both workers:

```bash
kubectl get nodes -o wide
```

Expected addresses:

```text
k8s-control-plane   192.168.122.131
k8s-worker-1        192.168.122.94
k8s-worker-2        192.168.122.38
```

All three nodes should report `Ready`. The control plane coordinates the cluster, while the workers provide capacity for application Pods.

If a worker needs to be rejoined after a failed attempt, run `sudo kubeadm reset` on that worker, prepare the node again, and use a newly generated join command.
